# 任务 05：请求失败后降级

**场景：** 主服务返回一个整数；主服务失败时，可以立刻提供默认值，也可以异步读取备用数据。

**产物：** `chapter03/task05.cpp`。用可重复的输入控制失败，不使用随机数。

## 固定输入

实现一个返回 sender 的请求函数，接收整数：非负输入 `x` 成功产生 `x * 2`；负输入在工作线程的 `then` 中抛出 `std::runtime_error`。错误必须在操作执行阶段发生，不能在 sender 工厂函数中提前抛出。

## 需要完成的工作

| 版本 | 对负输入的处理 | 消费方式 |
|---|---|---|
| A：直接传播 | 不处理，错误传到同步边界 | 在 `sync_wait` 外 `try/catch` |
| B：立即默认值 | 用 `upon_error` 返回普通整数 `0` | `sync_wait` |
| C：异步备用值 | 用 `let_error` 返回调度到线程池、100 ms 后成功产生 `99` 的 sender | `sync_wait` |
| D：异类型降级 | 用 `let_error` 返回成功产生 `std::string{"fallback"}` 的 sender | `sync_wait_with_variant` |

每个版本分别运行输入 `21` 和 `-1`。D 使用 `std::visit` 打印实际结果；B、C 保持与原成功路径相同的值类型。

## 约束与提示

- A 的失败分支后面放一个会打印标记的 `then`，确认它被跳过。
- B、C、D 的恢复之后再接观察回调，确认恢复后的正常下游会执行。
- D 的两种成功形态为 `set_value(int)` 和 `set_value(std::string)`。不要依赖 variant 的分支索引顺序。
- 独立尝试把 D 直接交给 `sync_wait`，记录编译诊断，再恢复正确代码。
- 错误恢复回调接收错误数据；本例抛出的异常通过 `std::exception_ptr` 传递。

## 验收

- [ ] 四个版本对 `21` 都产生 `42`，不执行恢复分支。
- [ ] A 对 `-1` 抛出异常，失败后的成功回调不执行。
- [ ] B 对 `-1` 得到 `0`；C 得到 `99`，且日志证明启动了备用异步操作。
- [ ] D 的负输入得到字符串，正输入得到整数；两个结果都属于成功完成。
- [ ] A 的错误不会被误写为“返回空 optional”。
- [ ] 能说明为什么 C 不需要 variant，而 D 需要。
