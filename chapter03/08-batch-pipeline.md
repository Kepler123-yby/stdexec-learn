# 任务 08：批量数据处理流水线

**场景：** 模拟图像处理服务：准备四帧整数数据，在 CPU 上逐元素变换，汇总每帧结果，再在固定线程上输出报告。

**产物：** `chapter03/task08.cpp`。这是综合练习，重点是把调度、数据并行、任务汇总与生命周期组合起来。

## 固定数据

帧 ID 为 `0..3`，每帧包含 `N=1000` 个 `std::int64_t` 元素。第 `id` 帧的第 `i` 个输入为 `id + i`，输出为 `2 * input + 1`。

每帧的结果结构包含 `id`、元素数量和输出总和。所有加法使用 64 位整数。

| 帧 ID | 元素数 | 预期总和 |
|---|---|---|
| 0 | 1000 | 1000000 |
| 1 | 1000 | 1002000 |
| 2 | 1000 | 1004000 |
| 3 | 1000 | 1006000 |

四帧总和为 `4012000`。

## 需要完成的工作

1. 建立一个准备数据的单线程 context、一个 4-worker CPU 线程池，以及一个输出报告的单线程 context。
2. 为每帧设计返回 sender 的工厂函数。准备阶段在准备线程生成 vector，并通过值移动进入后续管线。
3. 切换到 CPU scheduler，用 `bulk` 对 `[0, N)` 的每个元素执行变换。
4. bulk 全部完成后，在 `then` 中顺序计算这一帧的总和，得到固定类型的结果结构。
5. 用 `when_all` 组合四帧，汇总完成后切换到报告线程，在该线程输出四帧结果与总和。
6. `main()` 只在最终调用一次 `sync_wait`。使用普通循环计算独立的参考结果，逐项比较每帧的元素和总和。
7. 增加 `N=0` 和 `N=1` 两组运行，检查空数据与最小数据；再对比 `seq` 与 `par` 的结果。

## 约束与语法提示

- 本版本 bulk 的管道形式是 `sender | stdexec::bulk(stdexec::par, count, f)`。
- 若上游发送一个 vector，回调接收索引与该 vector 的左值引用；回调的返回值被忽略。每次只修改属于自己索引的元素，不改变 vector 的容量和大小。
- 通过上游的 `continues_on(cpu)` 或适当的 `starts_on(cpu, ...)` 让并行循环获得 CPU 线程池资源；`par` 自身不创建线程。
- vector 移入 sender 前保存 N，不从已被移动的 vector 推断循环次数。
- 不在并行回调里对共享 `sum` 做无同步累加。本题在 bulk 之后归约，先把同步关系做清楚。
- 逐元素核对可在归约回调中完成，再仅向下游传递结果结构；不要求把全部 vector 保留到报告阶段。
- 不在每个元素上打印或 sleep；可记录每阶段线程，并用少量同步记录统计参与计算的 worker。

## 验收

- [ ] N=1000 时每帧元素与普通循环参考完全一致，总和符合表格，总和合计为 `4012000`。
- [ ] N=0 时四帧总和都为 0，不访问空 vector 的首尾元素。
- [ ] N=1 时四帧总和分别为 `1、3、5、7`。
- [ ] `seq` 和 `par` 两种版本结果完全一致。
- [ ] 准备和报告回调分别运行在指定的单线程 context，bulk 及归约在 CPU 执行资源上运行。
- [ ] 四帧的报告顺序按 `when_all` 输入顺序处理，不依赖各帧完成先后。
- [ ] 主线程等待返回时所有数据访问已结束，随后才销毁上下文。
