# 任务 04：先查用户，再查订单

**场景：** 先根据姓名获得用户 ID，随后根据这个 ID 并发查询订单总额和积分。训练依赖关系与 `let_value`。

**产物：** `chapter03/task04.cpp`。复用任务 03 的线程池与日志方式。

## 固定业务规则

| 操作 | 输入 | 模拟耗时 | 成功结果 |
|---|---|---|---|
| 查用户 | `"Ada"` | 150 ms | ID `7` |
| 查订单总额 | ID `7` | 300 ms | 金额 `700` |
| 查积分 | ID `7` | 200 ms | 积分 `70` |

三个查询函数都返回 sender，真正的查询日志和耗时发生在启动之后。ID 必须从第一个查询的结果传下去，不能在后两个查询的调用处硬编码。

## 需要完成的工作

1. 构造 `姓名 → 用户 ID → 两个依赖查询 → 汇总字符串` 的任务图。
2. 用 `let_value` 接收用户 ID，在回调中构造并返回两个查询组成的 `when_all` sender。
3. 在最后的 `then` 中生成 `user=7, amount=700, points=70`。设计值传递，使用户 ID 也能到达汇总阶段。
4. 在主线程只调用一次 `sync_wait`。
5. 做一个独立的小对照：把“调用一个异步查询并返回其 sender”的回调放到 `then` 中，观察外层结果；再改成 `let_value`，比较实际执行日志和结果类型。

## 约束与提示

- `then` 返回 sender 时，它会把该 sender 当作普通成功值传下去；`let_value` 才会连接并启动返回的 sender。
- 子任务不能引用回调中即将销毁的普通局部变量。可以把所需 ID 按值捕获进子 sender；若保留引用，必须说明其所指对象由谁持有。
- 不在回调中嵌套 `sync_wait`。
- 保持两个子查询互相独立，不能查询完订单后才查询积分。

## 验收

- [ ] 构造管线时没有查询执行日志。
- [ ] 两个子查询都在用户查询完成后启动，并且执行区间有重叠。
- [ ] 空闲环境下总耗时趋近 `150 + max(300, 200)` ms，而不是三项之和。
- [ ] 最终汇总内容准确，主线程只有一次最终等待。
- [ ] 对照实验中，`then` 返回 sender 的版本不会自动执行内层查询；`let_value` 版本会执行并把普通结果交给下游。
